# Глоссарий угарных технических фраз

Живой словарь антипаттернов, рождённых в этом репозитории на живом мясе.
Каждая запись — с доказательной базой из diff'ов.

---

## Value-нюхание (value-sniffing)

**Существительное, ср. р.** Паттерн, при котором код вместо работы с типизированной
моделью на чтении принюхивается к сериализованным данным:
`Value -> .get("какой_то_ключ") -> unwrap_or("заглушка") -> повторное вычисление
того, что уже было вычислено при сборке`.

**Симптомы.** Цепочка `let Ok(value) = serde_json::from_slice::<Value>(..)` →
`value.get("evaluation")` → `eval.get("gates").and_then(as_array)` →
`state != "PASS"`. Структурный дрейф умирает молча: на месте исчезнувшего поля
вырастает `unwrap_or("")` и отчёт-цитата выходит полупустой, неотличимый от честного.

**Исторический экземпляр.** `quality_findings` в
`crates/devai-runtime/src/context.rs` до возврата-5: перечитывало quality-report,
который платформа сама же и собрала, и заново угадывало, что в нём не прошло,
хотя вердикт посчитал это ровно один раз — в `evaluation::assemble`.

**Лечение.** Одна типизированная модель на продюсера и консьюмера; ответ
вычисляется один раз при сборке и хранится в явном поле (`findings`);
читатель делает однотажный `from_slice::<QualityReport>` и рендерит хранимое.
Легаси-форма — явный типизированный случай, дрейф — громкая ошибка,
никогда — не заглушка.

**Синонимы в дикой природе:** гадание по строке, программирование через нос,
`unwrap_or`-молитва.

## Вахта против будильника (watch-vs-timer)

**Существительное, ж. р.** Вахтёр (watchdog) — процесс, который знает состояние
наблюдаемого. Будильник (timer) — процесс, который знает только время. Антипаттерн:
выдавать будильник за вахтёра — печатать «жив/умер» из факта тика или из отсутствия
строки-маркера, а не из авторитетного источника (таблица процессов, состояние в БД).

**Симптомы.** Монитор определяет смерть подопечного по `grep 'завершено' лог_обёртки`
— а лог пишет не тот процесс, за которым вахта. Или: фильтр событий покрывает только
счастливый путь, и крах неотличим от тишины — «молчание монитор принимал за порядок».

**Исторический экземпляр.** 2026-11-02,dogfood T2: вахтёр объявил
`T2 ФИНАЛ |state: ANALYSIS|`, хотя живой `task run` работал уже раунд аналитики v3 —
потому что маркер «CLI exit» нашёл в логе **двойника-призрака**, стартовавшего из
«заблокированного» классификатором вызова (тот не запустился «для классификатора»,
но запустился для ядра). Тот же день: два раннера на одной задаче породили
`expected version 2, found 3` — оптимистичный замок поймал, но вахтёр прозевал,
кто из двух мёртв.

**Лечение.** Вахтёр сверяется с единственным авторитетом: `pgrep`/PID-файл/состояние
задачи из хранилища — а маркеры из логов служит лишь вторичной подсказкой. Один
подопечный — один дневник: лог-файл привязан к incarnation (pid/start-time), иначе
его пишет труп. Фильтр событий обязан покрывать terminal-состояния (FAIL, crash,
timeout), иначе это будильник в плаще вахтёра.

**Синонимы в дикой природе:** heartbeat-ложь, вахта по чужому дневнику,
монитор-оптимист.
