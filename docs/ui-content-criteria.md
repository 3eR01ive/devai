# Критерий приёмки UI-аудитов: «содержимое окна», а не «процесс жив»

REQ-QA-01, задача 01a1acec (D1). Прецедент, из которого вырос критерий:
05.11.2026 — standalone devai-ui принят с «окно живо», внутри error page
«Operation was cancelled» (webkit2gtk ≥2.46 не диспатчит top-level навигацию
кастомной схемы, wry#1725). Smoke фиксировал «не упало» — содержимое никто
не видел. Критерий закрывает дыру в приёмке, не в коде UI.

## Формулировка

Аудит UI-задачи считается пройденным только при наличии на прогон ПАРЫ
артефактов:

1. `screenshot.png` — снимок окна webview (PNG, валидный, ≥1000 байт);
2. `axtree.txt` — текстовый дамп accessibility-дерева того же окна
   (AT-SPI-обход, строки `[role] 'name' ...`).

Съёмка не зависит от режима запуска: dev (vite http + debug-бинарь) и
standalone (tauri://localhost + release-бинарь) дают одно и то же окно и
снимаются одним инструментом. Пороги механически проверяемы по артефактам.

## Пороги (эталон — `crates/devai-ui/tools/ui_expectations.json`)

(a) ни одного error-page текста в дампе AX-дерева. Эталонный список
    (case-insensitive подстроки): «Operation was cancelled»,
    «not managed successfully», «Page not found»,
    «Web Content process crashed». Список расширяется данными файла.
(b) Дерево заполнено: ≥ 12 AX-узлов. Белый экран/error-page даёт 3–7
    (known-bad 05.11 — 3; на этой машине webkit 2.52.6 при отмене навигации
    текст в дерево уже не кладёт — порог (b) ловит именно это). Порог —
    измеренный край запаса (R3): живой дом БЕЗ данных («пустые проекты»,
    fixture qa-samples/edge-sparse, 05.11.2026 20:49 UTC) даёт 19 узлов —
    маржа +7 над порогом; порог на 5 выше верхней границы белого экрана.
    Прежние 20 съехали бы ложным FAIL на легитимный тонкий UI — 12
    зафиксирована по замеру, не на глаз; поверхность с более богатым
    ожиданием поднимает min_ax_nodes в СВОИМ ui_expectations.json.
(c) Обязательные навигационные элементы присутствуют. Набор зафиксирован
    исполнителем по `crates/devai-ui/frontend/src` (App.vue nav +
    router.ts/routes): nav-projects Проекты|#/projects, nav-tasks
    Задачи|#/tasks, nav-live Активные|#/live, nav-inbox Вопросы|#/inbox,
    nav-ops Операции API|#/ops. TaskDetail — не элемент навигации: это
    drill-маршрут `/task/:id`, недоступный из свежего окна без данных;
    его присутствие в прогоне обеспечивают router.ts и переходы, а не
    порог снимка (пункт порога — про СТАТИЧНУЮ навигацию окна).

Скриншот в (a)/(c) участвует как обязательная половина пары и как
артефакт для человеческой проверки rubric-слоем; текстовые пороги
механически читаются из AX-дампа (PNG-текст без OCR не матчится —
осознанная граница механической части, закрытая порогом (b): error-page
случай 05.11 имел в дереве и текст, и пустоту).

## Применимость (ратифицировано оператором: не только devai-ui)

Проба срабатывает, если у ЗАДАЧИ есть UI-поверхность:
- diff задачи (merge-base..HEAD + грязное дерево) затрагивает каталог
  поверхности-маркера: любой `tauri.conf.json`-корень или каталог с явным
  `.ui-audit-surface.json` (декларативный маркер для поверхностей не-tauri);
  ИЛИ
- в evidence задачи найдена пара артефактов (producer сам объявил UI-прогон).
Ни то ни другое → N/A (выход 0 с пометкой), задача не UI.
Затронута, но пары нет → FAIL: «окно живо» без съёмки не принимается.
Для каждой поверхности ожидания — её `tools/ui_expectations.json`; без
декларированных ожиданий проба FAIL'ит («набор элементов — данные, не
догадка»), что и не даёт критерию выродиться в devai-ui-only.

## Инструмент (harvest + gate)

`crates/devai-ui/tools/ui_content.py`:
- `snap --out DIR [--window S] [--pid P]` — снять пару с ЖИВОГО окна
  (AT-SPI gi + xdotool + import/scrot). Зависимости: python3(gi,Atspi),
  scrot/ImageMagick import, xdotool — только для съёмки; проверка пары
  зависимостей кроме stdlib не имеет.
- `check DIR` — пороги по паре; 0 PASS / 1 FAIL.
- `selftest` — прогон порогов на регрессионных образцах `qa-samples/`:
  known-good обязан давать PASS, known-bad — FAIL, edge-sparse (бедный
  живой UI) — PASS и отличаться от known-bad; иначе харнессу нельзя верить.
- `auto` — применимость + поиск пар в `<evidence>/ui/**` задачи
  (DEVAI_EVIDENCE_DIR текущих execution + все execution задачи в
  `<DEVAI_HOME>/evidence/<task>/`).
- `gate` — selftest + auto; точка входа платформенного гейта
  (quality.yaml v13, гейт `ui-content`).

Коды выхода (R1: обещанный класс = фактический код во всех die-пути):
0 PASS/N/A; 1 FAIL — вердикт по содержимому; 2 BLOCKED продюсера съёмки
(нет живого окна / gi / инструмента захвата — «не по чему оценивать»,
различим от FAIL); 127 BLOCKED платформенной пробы — невыполнимая проба
(битый/невалидный expectations-файл, неполная QA-база образцов,
провалившийся самоконтроль гейта): 126/127 → BLOCKED по config.rs:124-141,
не FAIL и не молчаливый пропуск. Файл ожиданий проходит fail-closed
валидацию при загрузке (R2): обязательные ключи error_texts, min_ax_nodes,
required_elements; потеря ключа — loud-ошибка 127, дефолтов нет.

Ritual producer'а (implementation-agent на UI-задаче): поднять окно,
`snap --out $DEVAI_EVIDENCE_DIR/ui/<run>`, проверить `check`, оставить
пару в evidence — гейт аудита сверит её сам.
