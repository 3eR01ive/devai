# Прототипы экранов (референсы)

Одноразовые HTML-макеты на РЕАЛЬНЫХ данных живого дома. Не часть приложения:
лежат как референс, по которому решается дизайн, прежде чем трогать основной
интерфейс.

| файл | что показывает |
|---|---|
| `tasks-list.html` | экран «Задачи»: таймлайн ролей в строке, группы, состояние раннера |
| `detail.html` | экран задачи (актуальный): вертикальный прогресс, один раскрытый шаг, вход/выход, вопросы у пунктов |
| `task-detail.html` | первая версия экрана задачи (до вкладов приёмки) |
| `prism/` | подсветка кода (Prism, локальные файлы — без сети) |

Экран задачи: вкладка «качество» считает вклад каждого пункта (вес, балл, вклад = балл×вес,
потеря), по умолчанию показывает только потери, отсортированные по силе; рядом — объяснение формулы.
Ссылки на код из отчётов раскрываются вставками настоящего кода с зафиксированного коммита,
с подсветкой и номерами строк.

Сборка (данные не выдуманы — читаются из `~/.devai`):

```sh
# список задач
./bin/devai --home ~/.devai --json task list > /tmp/tasks.json
#   затем поля каждой незакрытой задачи: task progress --json <id> → /tmp/rows.json
python3 gen_tasks.py            # → tasks.html

# экран задачи
python3 build_detail.py <task-id>   # → /tmp/proto/detail.json
python3 gen_detail.py               # → detail.html
```

`build_detail.py` дополнительно достаёт **настоящие куски кода** по ссылкам
«путь:строки» из отчётов, на зафиксированном коммите (`git show <commit>:<path>`),
чтобы отчёт проверки показывал код, а не только имя файла.

## Что эти макеты вскрыли в данных

- `pipeline.order` в `task progress --json` не знает стадию `STATEMENT`, а
  `graph.stages` знает — две разные оси этапов в одном ответе.
- У задачи в состоянии `REWORK` в графе нет узла «доработка»: последний шаг
  показан пройденным, хотя задача стоит именно в доработке.
- В контракте спеки у вопроса нет ссылки на пункт: аналитик пишет вопросы
  прозой, поэтому «вопрос у своего пункта» показывается только когда в тексте
  назван код требования. Остальные честно идут блоком «без привязки».
- Лимит попыток приходит только для ОДНОЙ роли (той, что сейчас работает),
  поэтому у остальных шагов видно «прогонов N» без «из M».
